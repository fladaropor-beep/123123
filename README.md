# ShoeShop — результаты заданий

## Состав
- `docs/diagrams/1.png`–`11.png` и `docs/diagrams/вся-программа.png` — 12 блок-схем из требований D01–D11 и общей логики приложения.
- `docs/модель_предметной_области.png` — модель предметной области.
- `docs/диаграмма_вариантов_использования.png` — диаграмма вариантов использования.
- `docs/диаграмма_деятельности_оформления_заказа.png` — схема процесса оформления заказа с дорожками.
- `docs/diagrams/erd.png` и `docs/erd.pdf` — ER-диаграмма.
- `docs/gantt.xlsx` — рабочий план-график.
- `tables/` — заполненные шаблоны Word.
- `db/import/` — 10 CSV-файлов, UTF-8, разделитель — запятая.
- `db/schema.sql` — DDL-схема для MySQL.
- `Отчет-дополнение.docx` — дополнение к отчёту, которое следует перенести в основной отчёт.

## Контроль качества и оговорки
1. Проверены заголовки и ширина строк CSV: все строки соответствуют числу столбцов.
2. Проверены уникальность `id` во всех 10 CSV и ссылки между справочниками/таблицами: дублирующихся ID и отсутствующих внешних ссылок не обнаружено.
3. Проверены уникальность логинов пользователей и артикулов товаров: повторов нет.
4. Даты проверены на календарную корректность. Исходная дата `30.02.2025` невозможна; в нормализованном `orders.csv` она оставлена пустой, поскольку корректную дату нельзя достоверно вывести из исходника. Уточните дату по эталону перед импортом.
5. Таблицы справочников `categories`, `manufacturers`, `suppliers`, `roles`, `orderstatus` вынесены отдельно; таблицы фактов ссылаются на них по ID.
6. В исходных данных пароли представлены открытым текстом. Для учебного импорта значения сохранены; в реальном приложении пароли необходимо хранить только в виде стойких хешей.
7. Фотографии товаров не приложены к исходному архиву; столбец `photo` сохраняет имена файлов из таблицы, когда они указаны.
8. В исходном архиве отсутствует основной файл отчёта и исходный репозиторий проекта. Поэтому `Отчет-дополнение.docx` — самостоятельный документ, а не объединённый основной отчёт.
9. PNG-диаграммы проверены на наличие и открываемость. Для дальнейшего редактирования желательно иметь исходники draw.io; они не входили в итоговый комплект.
10. Результаты автоматически проверены по структурным правилам, но окончательное соответствие всем критериям преподавателя требует визуальной проверки диаграмм и подтверждения неоднозначных исходных данных.
